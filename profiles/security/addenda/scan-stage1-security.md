## A security scan — security defects and security lenses only (security profile; supersedes the defect list, the `kind:` word and the lenses your SUGGEST block names above)
This scan looks for security defects and nothing else: a path by which someone crosses a trust boundary they should not — reaches data, an action or authority they lack, or runs their input as code or query.

- **Findings.** Report a defect only when it is a security defect. A crash, a logic error, a resource leak, a contract drift or a style point is left out, however real: no lens of this scan is asked to judge it. Every finding's `kind:` is `security:<class>`, one lower-case class word after the colon (`security:idor`, `security:sqli`, `security:ssrf`, `security:secret-literal`), named the same way every time.
- **Suggestions.** Every SUGGEST row names a `pass-sec-*` lens from your task string's list, never another. The reason says what the lens should chase in security terms: the entry point that reaches the files, the sink, the guard that looks missing, the trust boundary. Where you would have pointed a quality, consistency or delivery lens, point the security lens whose concern the code shows, or leave the file to the floor.
- **Where to point.** Entry points (route handlers, webhook and queue consumers, command handlers) get `pass-sec-authn-coverage` and `pass-sec-access`; code that builds a query, a command, a template or a deserialized object from input gets `pass-sec-injection`; file paths, uploads, archives and outbound requests get `pass-sec-boundaries`; credentials, tokens, keys and logs of user data get `pass-sec-secrets-data` or `pass-sec-tokens`; role and permission writes get `pass-sec-privesc`; cloud, cluster and host grants get `pass-sec-iam`; network exposure and runtime privilege in the shipped config get `pass-sec-infra`; check-then-act on balances, quotas, invites, one-time tokens, uniqueness kept only in app code, or a file checked before use gets `pass-sec-toctou`; model calls, agent tool handlers and prompt assembly from untrusted text get `pass-sec-llm`; manifests, lockfiles, CI workflows, install scripts and Dockerfiles get `pass-sec-supply-chain`.
