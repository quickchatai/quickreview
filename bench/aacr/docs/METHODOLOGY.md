# Benchmark methodology — QuickReview and six other reviewers on AACR-Bench

This document says exactly what was measured, how, with which builds and
prompts, and in what order the decisions were made, so a reader can reproduce
the numbers in the benchmark paper ([`../paper/benchmark.pdf`](../paper/benchmark.pdf)) and judge for
themselves whether the review was tuned to the test. Companion documents:

- [`THREATS-TO-VALIDITY.md`](THREATS-TO-VALIDITY.md) — the weak points, stated as
  plainly as we can.
- [`PROMPTS.md`](PROMPTS.md) — every prompt used to build the ground truth and to
  judge, verbatim.
- [`../METRICS.md`](../METRICS.md) — how to read the two tables and why they
  disagree.

Everything below is traceable to a file, a commit or a run directory. Run
directories live outside the repo, in `$QCR_BENCH_RUNS_DIR`, and are published
in the Hugging Face dataset and run archive<!-- TODO(launch): link -->; the ground-truth analysis scripts lived beside them in
`<runs-root>/analysis/`. Commits in brackets are builds in the pre-publication
history; the public history starts at its first commit, and each run's
`run.json` records the build it ran on.

## 1. What is measured

Every review is scored twice.

**The defect benchmark (our method).** A judge model reads a review — every
inline comment and the review body — next to a list of *verified real defects*
for that PR and decides, per defect, `found`, `partial` (counts ½) or `missed`,
wherever in the review it was said. It also grades every comment of the review:
correct-valuable, correct-minor, partly correct, wrong, unverifiable. Columns:
problems found (the lead number), recall, found per severity (high / medium /
low), weighted recall (3 / 2 / 1), share of comments correct, $ and minutes per
PR. Code: `src/bench/defects.ts`, `src/bench/defectjudge.ts`,
`bench/aacr/compare.py`.

**AACR-Bench's own metric.** The benchmark's harness, unmodified at a pinned
commit, compares each review comment with the dataset's reference comments on
the same file whose lines overlap within ±1 (the line gate), and asks a judge
model whether the two say the same thing. Recall = references matched /
references; precision = comments that matched a reference / comments. A comment
that is not on the reference list counts against precision even when it is a
real bug.

**Why both.** The defect benchmark measures what a review is for (finding the
real defects, saying true things). The AACR metric is the only number
comparable with the published leaderboard's method, and a check that we are not
simply measuring ourselves with our own yardstick. We lead with problems found
because that is what the reviewer is built to do; we report the AACR table in
full next to it, including where other tools beat ours (precision, F1).

## 3. The sandbox

All reviews and judging run locally in docker, never on the production VM and
never against GitHub's write API (`bench/aacr/bench.sh`, `bench/aacr/README.md`
"The safety model"):

- read-only root filesystem, `--cap-drop ALL`, `no-new-privileges`, non-root
  uid, pids/memory/CPU caps, tmpfs scratch; no docker socket, no ssh agent, no
  GitHub credential, no posting scripts, no `gh`;
- network: model/judge containers have ordinary egress for the model API;
  `prefetch` talks to github.com anonymously; `results`/`report`/rebuild steps
  run `--network none`;
- the prefetched repositories are a read-only volume, one bare store per PR
  (base and head only) so a reviewer cannot read the PR's future;
- the ChatGPT login (pi's OAuth) is mounted read-only and copied per case into
  the container's tmpfs **with the refresh token replaced by a dummy**
  (`src/bench/auth.ts`), so no benchmark process can rotate the operator's
  login. Codex, OpenCode and OCR reach the model through the same copy
  (Codex natively, OCR/OpenCode through the loopback `codex_bridge.py`);
- Claude Code uses its own API key from `~/.config/qcr-bench/claude.env`, passed
  with `--env-file`; the host's interactive Claude login is never mounted. Claude
  Code exists only inside its own image (the project's one sanctioned place to run Claude Code, commit `44a614f`).

**Why the chunked runs.** Arms that run one case at a time per set (OCR shape)
were split on rest145 into four parallel chunks (`-c1..c4`) to finish in hours.
For Codex and OpenCode a serial run had already reviewed 18/19 PRs; those were
kept (`all-*-rest145`) and the chunks cover the rest — no PR is reviewed twice
in the tables (`compare.py` takes the first run with a judgement per PR).

**One review per PR per reviewer.** Every number comes from a single run. On
the 40 original PRs, repeated runs of our reviewer earlier this week varied by
about ±1–2 found defects per 10 PRs (the benchmark paper, its run-to-run variance section).

## 5. Ground truth

The answer key for the defect benchmark lives in `bench/aacr/defects/<set>.json`
(and a readable `.md`). Each defect has a statement, sites, kind, severity,
evidence and "counts if" notes; each rejected claim is kept in `excluded` with
its reason, and the judge sees those. The exact prompts are in
[`PROMPTS.md`](PROMPTS.md).

**The original 40** (built 2026-09-26/27, earlier sessions; `method` field of
each file):

- smoke10 / dev10 / holdout10 (**v2**): per PR, a blind expert hunt from the
  diff and code; every candidate (the hunt, the AACR references with their
  agent-produced reference labels, every comment any reviewer posted in our runs — ours and OCR's,
  anonymised) checked against the code, merged and graded, exclusions recorded;
  an adversarial critic per set (12 corrections). v2 added the judge's
  new-defect candidates from 12 judged runs after checking (1 added, 2
  restated, 41 rejected).
- fresh10 (**v1**): blind hunt, then every comment of both of *our* arms
  (levers off/on) and the AACR references checked by a separate verifier.
  **OCR's comments were not candidates for fresh10.**
- Counts now: smoke10 34, dev10 37, holdout10 26, fresh10 29 defects — 126
  (34 high). Three CI-gate defects carry a `benchmark_limitation` note (§6).

**rest145 v1** (2026-09-27/28):

1. Code extraction (`analysis/2026-09-27-rest145/extract-in.sh`, `--network none`
   container): per PR the diff, diffstat, changed-file list, base and head
   versions of every changed file, the PR's bare git store, `meta.json`, and
   `references.json` (the AACR references, model names stripped).
2. Expert hunt, 29 Claude agents × ~5 PRs (`hunt.json`). The first launch was
   blind (no references); the operator then decided the ground truth should use
   the benchmark's reference comments as leads, the blind run was stopped (32
   drafts written) and re-run with references; the 32 drafts were re-checked as
   candidates. Each reference got a verdict. Result: 235 draft defects (46
   high); 134 references judged real, 973 rejected. Reviewer outputs were off
   limits to the hunt.
3. Reviews by default, low and OCR on rest145.
4. Independent verification, 29 Claude agents × ~5 PRs: every candidate — the
   hunt's defects, all 1,107 references, all 2,216 reviewer comments (default
   978, low 663, OCR 580) anonymised and shuffled, the arm key in a separate file
   the agents were told never to open — checked against the code, merged,
   graded, rejections recorded with a restatement of the claim.
5. Adversarial critic per ~15 PRs (10 agents): 6 corrections applied.
6. One PR (`ollama@2ed14f2`) whose default review was retried mid-verification
   had its candidate list renumbered; it was re-verified by one agent so every
   provenance id is right.
7. `assemble.py` → `defects/rest145.json` v1: **379 defects** (55 high / 113
   medium / 211 low), 2,118 exclusions; validated with the judge's own parser.

**rest145 v2 extension** (2026-09-28): the four new reviewers' comments —
1,527 candidates (OpenCode 557, pi-review 395, Codex 390, Claude Code 185 whole
review texts) — anonymised and shuffled, checked against the code and the
current truth by 31 verifier agents, then 11 critics checked every addition:
931 matched an existing defect, 691 excluded, 16 added, 1 removed by a critic
(4 critic corrections in total). Net **394 defects** (56 high / 114 medium /
224 low). The same pass added no defect on the original 40, so their files and
versions were **not changed** (their new exclusions stay in
`qcr-bench-runs/{orig40-code}/*/truth-ext.json`); only rest145 moved to v2
(commit `df1f82c`) and all seven reviewers are re-judged on it.

**Totals.** 520 defects: 90 high, 145 medium, 285 low. That is 126 on the
original 40 and 394 on rest145.

**Who built and who judges.**

- The ground-truth builder is Claude: the session model, Opus 5.5 for the
  2026-09-28 work.
- The primary defect judge is gpt-6-sol.
- A second defect judge, `claude-opus-5-5`, scored every review again (§6).

See [`THREATS-TO-VALIDITY.md`](THREATS-TO-VALIDITY.md) for what that does and
does not rule out.

**Independent-source subset.** Each defect's `provenance` records which
sources raised it: the hunt, the AACR references (`dataset_refs`) and the
reviewer comments. This lets us score every reviewer on a subset of the key:
the **369 of 520 defects (82 of 90 high)** that the hunt or an AACR reference
raised. These defects would be in the key if no reviewer comment had been a
candidate.

- 330 of the 369 were also raised by some reviewer.
- 39 have no reviewer among their sources.

`charts.py` computes the subset (the `independent-defects.jpg` chart), and
The benchmark paper has the table. On it, QuickReview default scores 86% under
both judges (80 of 82 high), against 84% on the whole key. The next reviewer
scores 71% (low), then 70% (Claude Code).

## 6. Judging

**Defect judge** (`bench.sh judge`, `src/bench/defectjudge.ts`): one pi session
per PR, `openai-codex/gpt-6-sol:high`, 1 round, read-only tools in the PR's own
checkout. It reads the review as scored (`results/all/<id>.json` comments,
deleted-line comments from `comments.json`, the review body `review.md`), the
defect list and the excluded claims, and answers per defect and per comment in
a strict JSON the parser checks. Verdicts are stored per ground-truth version and
judge model (`judge/v<version>-gpt-6-sol-high/`), so a changed truth never mixes
with old verdicts; a failed judgement is an error file that `compare.py` counts
as not judged (the row says INCOMPLETE) rather than as misses. Cases the review
never reached are not judged. Three CI-gate defects (a lint rule, stale generated
SQL, clippy) carry a `benchmark_limitation` note: a read-only review can find
them only by knowing the repo's CI; they are scored and also reported apart.

**Second defect judge** (`claude-opus-5-5`). The same judge prompt, the same
inputs and the same parser, run on Anthropic's model over the same 1,295
reviews (7 reviewers × 185 PRs).

- Its verdicts live in `judge/v<version>-claude-opus-5-5/`, beside
  `judge/v<version>-gpt-6-sol-high/`, so neither overwrites the other.
- `compare.py --judge-model claude-opus-5-5` prints its table, and
  `charts.py --second-judge claude-opus-5-5` draws `judge-agreement.jpg`.

How far it agrees with the primary judge:

- **Problems found:** every reviewer is within ±3 defects. For example,
  default is 437.5 under GPT and 439 under Opus; Claude Code is 324.5 and
  321.5.
- **Recall:** identical for all seven reviewers after rounding.
- **Per defect:** the same verdict (found, partly or missed) on 3,593 of
  3,640 reviewer-defect pairs (98.7%). For high-severity defects, 628 of 630.
- **Comments correct:** differs by up to 5 points. For Claude Code it is 81%
  under GPT and 86% under Opus. Its recall is the same under both.
- **Independent-source subset** (§5, 369 defects): the same ranking under
  both judges; default 86% under each.

**Why this makes the defect numbers trustworthy.** Every review is graded by
two independent judges from different model families, OpenAI's gpt-6-sol and
Anthropic's Opus 5.5, and they agree on almost every verdict. A preference
of one family for its own reviewers' phrasing, or one model's quirks in
reading the prompt, would show up as disagreement; there is almost none, and
the one visible gap (Claude Code's comments correct) does not touch any
recall figure. What this establishes is the *grading*: whether a review finds
a given defect, and whether a comment is true, is not an artifact of one
model family. It does not by itself validate the *answer key*. Both judges
score against the same 520 defects; the key rests on the verification
pipeline (§5) and the independent-source check, and its limits are in
[`THREATS-TO-VALIDITY.md`](THREATS-TO-VALIDITY.md).

**Judge errors and the Opus rate limit.** The Opus judge hit the Anthropic
organisation's rate limit for `claude-opus-5-5`. That limit is 50 requests
per minute, and a judgement averages about 1.7 API calls. The first pass
produced HTTP 429 error files. Here is what was done:

1. The queue was stopped and resumed at lower parallelism (`-P 3` ×
   concurrency 4).
2. A final `--resume` pass at `-P 1` re-ran every remaining error file.

Final state: **0 errors in 1,295 Opus judgements**. The GPT judge left 2
error files, which were retried to 0. `compare.py` treats an error file as
"not judged", never as a miss, and every final row reads 185/185.

**AACR eval** (`bench.sh eval`, `in-container.sh`): the harness's
`pipeline run --stage eval` unmodified, judge prompt run on
`openai-codex/gpt-6-sol:low` through a local shim (not the paper's Qwen3-235B
judge), 3 rounds averaged, `--line-k 1`. Sharding by PR (up to 6 processes per
variant) merges counts with the harness's own summary functions; on a copy of a
finished run sharded and unsharded results were identical per round, average
and PR. Arms without our severity tags score the `all` variant; compare.py
reads `all` for every arm and refuses to call runs with different judge lines
comparable. OCR is read by the harness's OCR reader; Codex, OpenCode, pi-review
and Claude Code write an OCR-shaped `review.comments` view read by the same
reader (Codex/Claude checked against the harness's own reader where structured
findings exist — identical).

## 7. Cost, tokens and time

$ per PR is pi's per-call price for gpt-6-sol ($2 / M uncached input, $0.20 / M
cached input, $10 / M output), summed over the main session and every lens pass
(`src/bench/cost.ts`, `compare.py`). Cached tokens are priced at the cached
rate: two calls were recomputed by hand from raw counts and matched pi to the
digit. Bridge-based arms (OCR, Codex, OpenCode) report OpenAI-style input
including cached tokens; the cached part is subtracted and priced at $0.20 / M.
Claude Code's cost is Anthropic's `costUSD` from its own output. The runs go
through a ChatGPT login and one API key; the dollar figures are list-price
equivalents for comparison, not invoices. The per-PR token table (uncached
input, cached input, output) for all seven reviewers is in
the benchmark paper. For Claude Code, the uncached column includes cache
writes.

Minutes are wall-clock per PR under the shared machine-wide scheduler (up to 10
reviews at once on one login), so they include contention; the tools that run
one case at a time per container are not directly comparable to ours on time.

## 8. Pipeline and reproducing

```sh
export QCR_BENCH_RUNS_DIR=~/qcr-bench-runs/runs   # any directory outside the checkout
bench/aacr/check_available.py --sets full                    # which PRs can run
bench/aacr/bench.sh build            # and: build --arm ocr|codex|opencode|pireview|claude
bench/aacr/bench.sh prefetch --set full --wait-rate-limit
# one arm = review → defect judge → AACR eval, machine-wide queue:
bench/aacr/arm.sh --prefix all-default --cases all30+fresh10+rest145 --parallel auto --eval 3
bench/aacr/arm.sh --prefix all-low --config review.preset=low --cases … --eval 3
bench/aacr/arm.sh --prefix all-codex --arm codex --cases … --eval 3        # likewise ocr, opencode, pireview
QCR_BENCH_CLAUDE_ENV=~/.config/qcr-bench/claude.env QCR_BENCH_CLAUDE_MODEL=claude-opus-5-5 \
  bench/aacr/arm.sh --prefix all-claude --arm claude --cases … --no-judge
bench/aacr/bench.sh claude-rebuild --arm claude --run <run> --set <set>    # prose → comments, then eval
bench/aacr/compare.py --cases all30+fresh10+rest145 "default=…" "low=…" …  # both tables
bench/aacr/compare.py --judge-model claude-opus-5-5 --cases …  "…=…"       # the second judge
uv run bench/aacr/charts.py --cases all30+fresh10+rest145 --second-judge claude-opus-5-5 "…=…"  # the JPGs
```

Ground truth for new PRs: `<runs-root>/analysis/2026-09-27-rest145/` held `extract-in.sh`,
`candidates.py`, `verify-workflow.js` (the verify/critic orchestration),
`assemble.py`, `extend_prep.py`, `assemble_ext.py`, the batch files and logs.
The hunt, verify and extension prompts are reproduced in `PROMPTS.md`.

**In this repo**: the harness wrapper, every arm, sets, ground truth,
the compare/charts scripts, METRICS and the two papers (with the figures they
include). **In the Hugging Face dataset and run archive<!-- TODO(launch): link -->**: the run directories (reviews, transcripts,
